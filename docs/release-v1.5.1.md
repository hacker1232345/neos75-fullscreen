# Neos75 v1.5.1：进度条真的去掉了，文字默认不再挡原厂界面

这一版修的是两个实测反馈。两个都不是「参数没调好」，而是**走错了分支**。

---

## 一、强制模式没去掉进度条

### 现象

用「无验证应用补丁」刷过之后，浏览器上传图片时那个绿色进度环还在，中央的 `0%` 也还在。

### 根因

补丁链是三层的：第一层把媒体区改成全屏，第二层去掉进度相关的东西，第三层放覆盖组件。旧代码在强制模式下是这样写的：

```python
layers = plan_chain(applicable) if applicable else [ms[0]]   # 旧
```

`ms[0]` 是链首那一层，也就是**只有第一层**。于是强制模式永远只套第一层 —— 而进度环的补丁在第二层。刷完之后 prepatch 报告是「成功」，实际上那 5 条字节根本没被碰过。

`tools/firmware_image.js` 里是同一个逻辑（`else if (force) layers = [manifest]`），两端都错。

### 改法：先试后写

强制模式现在**从链首开始，逐层核对旧字节**，对得上才应用；任何一条对不上就停在该层之前。多条链各自算出「能套最多的前缀」，再取最长的一条。

关键约束：**必须从链首连续判断，不能从中间层起步。** 第一版写成「每个 profile 都当起点」，实测在 clean 镜像上强制时只套了第三层的 2369 字节 —— 第二层没套上却把挂在第二层后面的第三层单独套进去了，这种「半套」状态比不套更危险。

```
known-clean 镜像 + force  →  widget + widget-none，2369 字节，forceBlind=False
v1.5.0 设备镜像 + force   →  只套 widget-none，366 字节
clean 改一个字节 + force  →  一层都对不上，0 字节改动，forceBlind=True
```

### 对用户说人话

一层都对不上时程序会照旧只套最基础的那层（这是兜底，不是「适配成功」），但会在**擦除之前**就说明：

> 进度条不会被去掉。布局对不上，只套了最基础的一层补丁：浏览器上传时的进度条和覆盖层会保留，其余功能正常。完整备份已保留。

完成时的提示也从「全屏补丁已完成」改成「**补丁已完成（进度条仍在）**」，不再假装成功。

### 顺带修掉的一个隐患

尾部 4096 字节（用户配置区）的保护原来是 `if not force` 才校验，也就是**强制模式能改用户的现场配置**。现在改成无条件校验，两种模式一致。

## 二、每一页都叠着四行字，还压住原厂状态栏

### 现象

装上组件后翻任何一页都看到四行字。第六页早有验证、看着正常，但其余页面本来就该是原厂画面。

### 根因

构建器把页掩码写死成 `0x3f`（六页全开），而且 `--pages` 的默认值就是 `6`。这是我们图省事，不是设计。

### 改法一：没选中的页面主动清空

`TICK` 段新增 `tk_clear` 分支：页掩码里没选中本页时，把本页四个 label 全部指到空串（`D_NONE = 52`），并把 `C_APPL[page][0..3]` 写成 `-1`。靠 `-1 + 1 == 0` 判断「已经清过了」，保证只清一次，不会每帧重复写。

段布局没变（`tick` 仍是 512 字节），所以这个改动落在原来的零字节区，不需扩段。

### 改法二：新增一层，只做「关掉」

`firmware/profiles/widget-none.patch.json`（`widget-none-ec412e09`）挂在 `widget-dce6dce7` 之后，只改 366 字节 / 2 扇区。老用户从 v1.5.0 升上来只要这一层，不用重刷 2369 字节。

页掩码默认 `0x0`，CLI `--pages` 默认值从 `6` 改成 `none`。

### 改法三：协议层承认「0 就是关」

真机实测：发掩码 `0` → 回 `0xFE`（接受），随后 `probe` 变 `0xFD`。所以 0 是**干净的关闭**，不是错误值。

- `native_widget.js`：`maskPacket` 校验 `0..0x3f`；`maskFromPages([])` 返回 0 而不是抛错。
- `push_widget.js`：`mask 0` / `mask none` / `mask off` 都接受。
- `dash_bridge.py`：`native_frame` / `native_mask` 校验 `0..0x3f`。
- `glass.py`：`_native_mask()` 空选返回 0；`native_pages()` 不再对空选报错，改走关闭路径，提示「所有界面恢复原厂内容」。
- 桌面程序：新增「关闭文字组件」按钮，点一下把页选择清空再写掩码 0。

「连续发送」仍然要求至少选一页 —— 关掉是另一条路径，不是「往零页发帧」。

## 四、仍然没解决的

- **屏幕主控 UB32F341S 的 SWD / BOOT0 焊盘没找到**。屏幕代码区刷坏目前没有恢复通道。这是整个项目最大的未知风险。
- 无线模式下文字通道未验证。
- 中文仍然显示为空（只接受 ASCII `0x20`–`0x7e`）。
- 强制模式仍不代表「已适配」。布局迁移过的固件能套到哪一层就是哪一层，套不上的补丁不会凭空生效。

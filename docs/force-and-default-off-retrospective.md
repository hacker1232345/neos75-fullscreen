# 强制模式与默认关闭：这一轮绕了哪些远路

## 要做的事

用户实测给了两条反馈：①发布版用「无验证」刷过之后，浏览器上传的进度环还在；②键盘每一页都叠着四行字，还压住原厂的状态栏。

三条硬约束：不能碰原厂页表与页面处理函数；已在设备上的固件要能「只补差量」升级，不能要求重刷整层；任何会让用户误以为成功的路径，必须在擦除之前说清楚。

## 做对的

1. **先看分支逻辑，不先调参数。** 进度环没去掉这件事，第一反应会去怀疑补丁字节写错、地址错了，实际是 `else [ms[0]]` 这一句让第二层根本没被执行。翻出 `build_fullscreen.py:99` 和 `firmware_image.js:99` 对照，两端同一个错，才敢断定是逻辑而不是数据。
2. **强制模式改成「先试后写」而不是「一律套全链」。** 未知布局上套不匹配的补丁会写坏代码。逐层核对旧字节，对得上才应用，是最小风险的方案。
3. **发现「半套」比「不套」更危险。** 第一版按「每个 profile 都当起点」算，结果 clean 镜像上只套了第三层 2369 字节 —— 第二层缺失、第三层却上去了。改成必须从链首连续判断，并且把这条理由写进代码注释，避免以后又被人「优化」回去。
4. **把「关掉」做成协议里的合法值，而不是单独一条命令。** 真机先验掩码 0 回 `0xFE`、再 `probe` 变 `0xFD`，确认是干净的关闭，才动手改校验范围。这样固件、桥接层、UI 三处只要统一放宽一个下界，不需要新增协议分支。
5. **差量层而不是重刷整层。** 老用户从 v1.5.0 升到「默认关闭」只要 366 字节 / 2 扇区，不用重写 2369 字节 —— 少写一个扇区就少一次刷坏的机会。
6. **profile 可重现。** `make_widget_profile.py` 重跑一次逐键一致（`DIFF keys: []`），并加了「按代码哈希反查父层」的 `lookup_parent()`，避免父层名写错导致链断掉。

## 绕的远路

| 走错的地方 | 花了多久 | 怎么发现的 | 教训 |
| --- | --- | --- | --- |
| 以为「进度条没去掉」是补丁字节写错，先去核地址与 CRC | 约 40 分钟 | 打印 `appliedProfiles` 才发现只有一层 | 症状在「刷完之后」，根因可能在「选层之前」 |
| 强制模式第一版「每个 profile 都当起点」 | 约 25 分钟 | 在 clean 镜像上实测，改动字节数 2369 而不是 2395，缺了 clean 层 | 链式补丁只能从链首连续判断 |
| `native_widget.js` 改了校验却忘了同步 `test_native_widget.js` 的断言 | 约 10 分钟 | `npm test` 报 2 组 FAIL | 改校验边界必然要改断言，两件事同一个编辑里做完 |
| 用 heredoc 写含 `'\n'` 的 Python，反斜杠被吃掉 | 约 15 分钟 | `SyntaxError: unterminated string literal` | 含转义序列的代码一律用 write 工具直接落盘 |
| 先把所有文件改成 LF 再改回 CRLF | 约 30 分钟 | `git diff --stat` 虚涨到 1235 行 | 改行尾前先 `git show HEAD:<file>` 数 CRLF 数量，逐文件对齐，别全仓一把梭 |
| `make_widget_profile.py` 的 `--parent` 默认值按 clean 哈希算，导致 widget-none 的父层算错 | 约 10 分钟 | 重跑比对出现 `profile: widget-ec412e09` 而不是 `widget-none-ec412e09` | 默认值要能从目录里反查，不能假设输入镜像就是 clean |

## 留下的债

- `forceBlind` 目前只是「告知」，不改行为 —— 用户勾了强制就继续刷。要不要改成「直接拒绝」，取决于用户愿不愿意承担「刷了但没去掉进度条」的浪费。这一轮选了告知，因为拒绝会让人以为程序坏了。
- `widget.patch.json`（全页开）保留着只为兼容老用户升级。它和 `widget-none` 组成一条越来越长的链，将来如果再加「部分页开」的预设层，链会变成四条，`plan_chain` 的测试要用生成式写法，不能一条条手工断言。
- 屏幕主控 UB32F341S 的 SWD / BOOT0 焊盘仍然没找到 —— 屏幕代码区刷坏就没有恢复通道，这一版没有改善。
- 强制模式对「布局迁移了但只迁一部分」的固件，只能套到第一个对不上的层为止。理论上可以做「按段跳过」，但那会让「套了几层」变成一个模糊的中间态，风险比收益大，暂时不做。

## 后续风险清单

| 风险点 | 触发条件 | 后果 | 前兆 | 对策 |
| --- | --- | --- | --- | --- |
| 强制模式盲套链首写坏未知固件的代码区 | 布局迁移且用户勾选「无验证」继续刷 | 屏幕不启动，需拆机 | 提示里出现「进度条不会被去掉」但用户仍点确认 | 程序已前置告知；刷前完整备份 + `restore` 可回退；屏幕侧暂无 SWD 通道 |
| 老用户从 v1.5.0 升级时链断掉 | `widget.patch.json` 被误删或改哈希 | 识别成 unknown，强制模式只能套链首 | `firmware_info` 报 `kind=unknown` 且 `pending` 为空 | 该文件是「旧版带文字」的唯一身份，不许改内容；`test_profiles.py` 断言 5 个 profile |
| 掩码 0 在某些页被当成「未初始化」而报 0xFD | 设备停在未初始化页时 probe | 用户以为关闭失败 | `probe` 一直回 0xFD 而不是 0xFE→0xFD | 文档已写明 0xFD 是「该页尚未初始化」；UI 提示「翻到已选中的界面」 |
| `tk_clear` 只清一次的逻辑被误改 | 有人把 `-1 + 1 == 0` 当成冗余优化掉 | 已关闭页面的旧文字永久挂在屏上 | 关掉之后翻页仍见旧字 | 代码注释写明用途；构建器断言段布局不变；重跑 `test_profiles.py` |
| 尾部 4096 字节保护回归成「仅非强制」 | 有人为「强制要彻底」放宽条件 | 强制刷写改掉用户配置（键位、灯效、绑定表） | 刷完设置全部回默认 | 现为无条件校验，任何放宽都要先改测试 |
| 发布包与仓库代码不一致 | 打包前忘了跑测试 / 用了旧 dist | 用户拿到的 exe 行为与文档不符 | `--self-test` 的 version 与 tag 不符 | 打包后必须跑 `--self-test` + `--gui-smoke` + `ci_smoke.py`，三者 version 都要对上 |
| 行尾混乱导致 diff 虚涨、真改动被淹没 | 跨工具链编辑（bash 脚本写文件） | 评审时看不出实际改了什么 | `git diff --stat` 行数远超预期 | 提交前必看 `--stat`；逐文件对齐 HEAD 的 CRLF 数量 |
| profile 生成器默认父层算错 | `--base` 不是 clean 但没传 `--parent` | 链衔接断，老用户升级失败 | `profile` 名少了 `none-` 前缀、`pending` 为空 | `lookup_parent()` 按代码哈希反查，多候选直接报错要求显式指定 |
| 中文仍是空白 | 用户选中文标签的组件 | 屏上少字，看起来像坏 | 该行为空白或只剩数字 | 文档与 UI 文案都写明「只接受英文数字」 |
| 屏幕刷写超时 180 秒 | bootloader 时限到了才回验 | 步骤 5 必然失败，靠单独 verify | 日志出现 180 s 超时 | 已知常态：`flash` 后单独跑 `verify`；`leave` 报 disconnected 是正常的 |

排序依据：后果严重度 × 发生概率。前四条（写坏未知固件、链断、掩码语义、`tk_clear` 被误改）都是「一次性造成不可逆损失或功能永久失效」且「有人会踩」，所以排在最前。

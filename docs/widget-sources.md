# 天气、Codex 与屏幕切页

在小组件页的“天气与 Codex 设置”搜索城市，选择准确的地区。天气是可选项，只有添加天气组件并预览/同步时才请求所选城市的天气。没有自动 IP/GPS 定位。当前天气来自天气模型，缓存十分钟，失败后至少一分钟再试，保留旧值时显示缓存，超过一小时隐藏旧温度。界面与画面包含 Open-Meteo 署名。

Codex 默认跟随 `CODEX_HOME/sessions`（未设置时 `~/.codex/sessions`）中最近更新的任务，只检查最近七个日期目录和尾部至多 1 MiB 的完整事件。可以输入完整任务 ID 来固定任务。只导出状态与事件时间，不把提示词、对话、工具参数、输出或身份数据放到小屏。没有明确结束事件就不认为完成；长期无事件也不认为失败。超大记录可能无法提取状态，此时退化为文件近期活动提示。

本地日志不是稳定的公共 API，不能保证所有 Codex 桌面版本、云端或其他主机任务都可自动读取。自有客户端可消费官方 [app-server 生命周期事件](https://developers.openai.com/codex/app-server)，把状态快照原子写入 `CODEX_HOME/neos75-progress.json`，例如：

```json
{"state":"running","updated_at":1800000000,"thread_id":"任务完整ID"}
```

`updated_at` 是 Unix 秒数；示例时间必须替换成实际事件/心跳时间。可用状态 `running`、`waiting`、`completed`、`failed`、`interrupted`、`unknown`。仅接受最近 120 秒内且与所选任务一致的快照；连接保持活跃时可每 30 秒写一次相同已知状态。断开时不要继续虚构心跳。`turn/completed` 必须检查真实 `turn.status`，不能无条件写 completed。`activeFlags` 中的 `waitingOnApproval` / `waitingOnUserInput` 可映射 waiting。程序不安装或覆盖 Codex hooks/notify，不启动 app-server。

“固定当前组件页 / 自动轮播”控制电脑端 JPEG 分页，正在发送的一帧会完整结束后再切页。“上一界面 / 下一界面”控制键盘原厂界面，必须先停止同步。

## 协议依据与未完成的硬件能力

本地保存的官方 `_bs_flat.js` 中 `SCREEN_CONTROL=0x39`、`FLIP_DOWN=1`、`FLIP_UP=2`，由 `buildScreenPacket` 生成运行时命令。新工具只允许这两种操作，不能发送亮度、恢复出厂或未知控制字。

图片流 `UB` 头只含宽、高、帧数、延迟、帧长度，传输头与帧中没有独立目标页参数。可证实当前上传工具写同一个媒体通道；尚无证据证明六个原厂界面拥有六个可独立上传的媒体缓冲区。本版没有用猜测的页号或地址写入固件。

若要保留原图片/GIF，又在另一个原厂界面放动态组件，需要继续定位 MCU 的页面对象、媒体解码缓冲区与页面切换处理，验证内存容量和媒体区互不覆盖，并对每种固件构建分别做离线补丁与回滚验证后再真机验收。这不是单独发送官方翻页命令能够实现的。本版停止同步后不会恢复已被组件覆盖的图片/GIF，须用官方程序重新导入。

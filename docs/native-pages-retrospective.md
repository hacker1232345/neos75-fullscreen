# 任意页覆盖组件：复盘

## 要做的事

用户原话：「第六页主页显示正常，现在把它添加到正式版功能里。让每一页都可以被自定义，同时官方原来的页面也要保留，让用户自由选择放到哪一页。」

翻译成工程要求，有三条硬约束：

1. 功能要进正式仓库，不是留在实验分支。
2. **每一页都能挂**，不是只有第 6 页。
3. **原厂页面必须保留**——用户能自由选页，而不是被永久占用一页。

第 3 条直接把实验分支的做法否掉了。

## 做对的地方

### 一开始就判断「分支的做法不满足需求」

分支 `research/native-page6` 的做法是把第 6 页的创建函数整段替换（`0x379ac..0x37ef4`）。这在「只要第 6 页」的场景下最省事，但第 6 页原本的东西就永久没了。

先算清这个账，才没有在分支的做法上继续打补丁，而是改成覆盖式。**如果先动手改再发现问题，整条逆向链要重做一遍。**

### 覆盖式只改两处，且都用断言守住

- 命令表 `0x35316` 的 2 字节：`0x3D` 命令从原厂默认返回改指我们的接收器。
- 代码区空闲带 `0x4aacc` 起的代码。

页表和六个原厂页面的 `enter` 回调**一个字节都没动**。构建器把这两条写成断言（`page_table_untouched` / `vendor_enter_untouched`），每次构建都检查，改坏了当场报错而不是刷到设备上才发现。

### 页号用固件自己的变量，不猜

最初想用 `GETSCREEN` 的返回值去比对页表里存的 root 指针。实测 `dbg8.bin`：逐页翻 7 次，6 个槽全部不匹配。原因是 `GETSCREEN` 返回的是当前屏幕对象，而页表槽里存的是创建时的那一个，两者不保证同一个指针。

改成读固件自己维护的页号变量 `PAGE_VAR = 0x200044ad`（0 基）。实测翻页 `02 → 03` 立即跟随。**这是固件已经在用的变量，语义不会骗人。**

### RAM 只有 64 KB —— 这条差点让整个方案假成立

前三版固件（`ov6b`/`ov6d`/`ov6e`）全部 probe 失败，我以为是代码逻辑问题。真相是：`CTX_WORD = 0x20011110` 和 `0x20012208` **根本不在 RAM 里**——这颗芯片只有 64 KB（上界 `0x20010000`）。

静态扫描「这段地址没有代码引用」被当成了「可以用」，但那只是说没人引用，不是说硬件能写。运行时写入扫描（95 个网格字）才查出**只有 48 个可写，最高 `0x2000fca0`**。

换成 `0x2000c610`（最大空洞 2547 B）后 probe 直接从 `0xFC` 变 `0xFE`。

**教训：静态分析的「没人用」和硬件的「能写」是两件事。凡是往 RAM 里塞自己的数据结构，必须做一次运行时写入验证。**

### Keystone 编绝对地址长跳会错位

`bl #0x2637c`（`lv_mem_alloc`）被 Keystone 编成了 `bl #0x2638a`，偏移 +0xE。所有绝对地址的 `bl` / `b.w` 全都偏了。反汇编看 `push/pop/ldr` 都正常，只有目标地址是错的——**这种错误不看目标地址就发现不了**。

改成自写 THUMB-2 编码器（`enc_bl` / `enc_bw`），并加 `fix_branches()`：从源码文本收集期望目标、用 capstone 反汇编产出的字节逐条核对，数量不符直接抛异常。与 Keystone 对 10 个偏移（含负数）**20/20 逐字节一致**才收工。

编码位域踩了四轮：`hw1` 前缀是 `0xf000` 不是 `0xf800`；`J2` 在 `<<11`；BL 第二半字基底 `0xd000`；B.W 基底是 `0x9000`（不是 `0x8000`，也不是 `0xc000`）。

### 每页独立缓冲，而不是共用一个

首版六个页面共用一个四行缓冲，翻页看到的是同一份内容。改成 `C_RECV[6][4]` + `C_APPL[6][4]` + `C_BUF[6][4][32]`（`CTX_SIZE` 384→1104），每页有自己的文字、自己的「已应用」记录、自己的 seqlock。

## 绕远路的地方

| 走的弯路 | 为什么错 | 代价 |
| --- | --- | --- |
| 先试「改 `enter` 桩」 | 桩确实跑到了，但拿不到页面对象 | 刷了 `ov6.bin` 6 个扇区，白刷 |
| `GETSCREEN` 指针比对页表槽 | 两者不保证同一指针 | 刷了 `dbg8.bin`，翻 7 次全 `0xEB` |
| 用 `0x20011110` 当锚点 | 地址在 RAM 之外 | 三版固件 probe 全失败 |
| 相信 Keystone 编绝对地址长跳 | 它编错 +0xE | probe 恒 0xFC，查了三轮 |
| `sweep.js` 用 `readSync` 读 HID | 同步读在 HID 上会永久挂起 | 一个后台 job 挂死要 kill |
| `probe_dbg3.py` 把 ACK 写到 `[sp+0x22]` | handler 自己 push 了 20 B + sub 8，必须写 `[sp+0x3E]` | 退回原厂状态码 `fc`，误导一轮 |

## 留下的债

- **屏幕主控 UB32F341S 的 SWD/BOOT0 焊盘仍未找到。** 如果屏板代码区刷坏，没有恢复通道。本版只改 3 个资源区扇区，不动引导和启动代码，但这个风险一直在。
- 字模只验证 ASCII `0x20`–`0x7e`。中文、emoji 一律变成空格——不是「显示不出来」，是**被替换成空格**，用户会以为是空白页。
- 四行固定行高，不换行、不滚动。文字超过 47 字符会被截断。
- 无线模式（2.4G）没验证过，只测了有线。
- 长跑只到 40 轮 / 2 分钟量级，没有数小时监测。
- 屏幕不能主动退出 DFU，每次刷完靠约 180 秒超时或拔插。
- Mac / Linux 的 USB 侧仍然没有真机验证。

## 五列风险清单

| 风险点 | 触发条件 | 后果 | 前兆 | 对策 |
| --- | --- | --- | --- | --- |
| 刷入时把屏板代码区刷坏 | 刷写中途断线、或误用别的 profile | 屏幕黑屏，无恢复通道 | 刷写报 `endpoint stalled` 且重试全失败 | 刷前整片备份必做；只走最小扇区；`KEEP_SECTORS` 硬保护；**不要在没有备份的情况下刷** |
| 用户以为中文能显示 | 选了中文主机名/中文进程名 | 屏幕上那一段变空白，看起来像坏了 | 预览里已经是空白 | 预览就显示真实会写上去的 ASCII，UI 明确提示「中文会变成空格」 |
| 页掩码写到已选之外的页 | 手动跑 `mask` 命令写错位 | 原厂页面被叠上文字，用户以为页面被改坏 | probe 在没选的页回 `FE` | 桌面程序只按选中的页算掩码；命令行工具默认不改掩码 |
| 设备停在未选中的页面时推送 | 用户在第 3 页，但只选了 1/2/4 | 帧被拒（`FD`），用户以为坏了 | `{"error":"该页尚未初始化"}` | 常驻循环不因单帧被拒而退出，只提示「翻到已选界面」 |
| 同一时刻两个程序抢 HID | 官方驱动程序和本程序同时开 | 其中一方拿不到句柄或写失败 | `failed to open device (error 5)` | 只开一个；连续发送前关官方上传任务 |
| 长时间连续写 RAM 累积异常 | 数小时连续 loop | 未测；可能句柄泄漏或设备忙 | 帧开始零星失败 | 建议不超过数小时；失败会打印到诊断 |
| 打包版找不到 `push_widget.js` | 打包白名单漏 `tools/`（历史上漏过两次） | 界面正常但「发送一帧」永远失败 | 报「tools/push_widget.js 尚未提供」 | `build_exe.py` 白名单已含 `tools`；`ci_smoke.py` 在打包版上跑门控 |
| 固件层与设备实际层不一致 | 用户自己刷过非本项目的固件 | 生成出来的镜像层错位，刷进去花屏 | `identify()` 返回 `unsupported-version` | 纯哈希识别，认不出就拒绝写；强制模式只套链首 |
| 前端 `native_pages` 持久化旧值 | 用户改过页选择后升级程序 | 旧配置被当成合法值 | 校验失败提示 | `_page_selection()` 每次校验 1..6、去重、排序 |
| 屏幕进入 DFU 后无人管 | 刷完不拔插 | 180 秒内不能做别的事 | 设备以 `0x5542:0x1000` 出现 | 刷完立即 `leave`；或等超时自动回应用态 |

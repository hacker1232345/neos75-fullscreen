# v1.1.3 自动选择固件配置复盘

Issue #1设备的后台版本号、VID/PID与原验证设备相同，但实际程序和数据布局发生迁移；原补丁20条记录有18条在原地址不匹配。v1.1.2强制覆盖固定地址不能解决这种布局变化。

现增加构建配置目录，以备份前487424字节精确SHA256匹配原版或已补丁代码。Python和Node均读取同一组配置；原验证构建和Issue #1构建在一个程序内自动选择对应地址，生成、现场检查、刷写、回验和恢复保持同一配置。源文件长度、旧字节、目标代码哈希和目标重建一致性检查保留，末尾4096字节现场数据来自本机备份。

新构建媒体页入口0x3750C，相关静态/GIF路径和尺寸字段分别定位，20条旧字节均匹配。两种配置的载荷都只改27字节。新构建ARM仿真得到容器位置[0,0]、尺寸480×360、侧栏标志3和480×360查询回报；6组容量指令执行值符合全屏需求。外部调用使用桩，不模拟LCD、硬件JPEG或真实堆。

独立离线核验使用本地两份真实备份，结果与此前各自生成目标完全一致；Python/Node一致、末尾现场数据变化保留、改动代码拒绝、已全屏识别、4KB/8KB擦除及失败后恢复模型通过。公开CI以合成配置测试自动选择，不上传真实备份；摘要见 evidence/firmware-profiles-validation.json。

原验证构建已有图片/GIF实机验收；Issue #1构建仅完成离线验证，界面和发布说明明确标注待实机。用户提供的完整备份和生成整片候选保留在本地，不上传仓库或Release。

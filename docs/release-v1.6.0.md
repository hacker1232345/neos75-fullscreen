# Neos75 全屏工具 v1.6.0

这一版解决的是**你的键盘和别人的键盘不一样**这件事。

同款 AULA Neos75 出厂刷的固件版本很多，程序原来的做法是把补丁打在固定偏移上（「0x2c53c 这一格」），所以只要固件布局挪动一点，整条补丁链就废了，只能人工反汇编、重新找位置、单独做一份配置。这一版把「记格子」换成「记字节」——补丁记住的是**它要改的那段字节长什么样、周围是什么**，布局挪多远都还认得出来。

## 别人家的固件现在能自动适配

三个入口，从最省事到最可控：

```sh
python tools/adapt_firmware.py --firmware backup.bin            # 只看结论，不写文件
python tools/adapt_firmware.py --firmware backup.bin --build out.bin   # 直接出可刷镜像
python tools/adapt_firmware.py --selftest                        # 离线自检，不需要设备
```

完全不懂命令行的用户还有一条路：把导出的 `.bin` 备份**直接拖进一个 issue**，打上 `firmware-adapt` 标签，GitHub 会自动算完并在 issue 里回帖，产物挂在 Artifacts 里自己下。整条链路不接设备、不刷写、只算字节。

## 改了什么

**内容锚点**（`tools/make_anchor.py` → `firmware/anchors/*.json`）
每条就地改写的补丁都记一段**全片唯一**、且**不盖住本层其它补丁字节**的上下文。`reference` 20/20、`clean` 5/5、`widget-none` 2/2 都有锚点。

**符号签名**（`tools/symbols.py` → `firmware/anchors/symbols.json`）
注入的覆盖组件那段代码里含着 11 个厂商函数的绝对地址，换固件这些地址会一起变，按字节搬就成了「调用一个毫不相干的函数」。所以给这 11 个函数各取 16 字节入口当签名，再加 `TBB`、`CMD_RET` 两个结构锚点，共 13 项，在两份不同镜像上都能唯一定位。找到之后**按新地址重新汇编**，而不是搬运。

顺带一个结论：**RAM 变量不需要签名**。它们是固定的 `.bss` 地址，跨固件不变；只有函数代码要重定位。

**可重定位构建器**（`tools/build_widget.py`）
`relocate(syms, free)` / `restore(old)` / `visible_symbols()`，`patch()` 增加 `strict=False`（只在符号已经换好时使用）。命令项的写入公式修正为 `(F_RECEIVE - (CMD_TBB + 4)) // 2` —— 必须 `+4`，因为 `tbb [pc,r]` 用的是 `pc+4` 作表基址。

**链式适配器**（`tools/adapt_firmware.py`）
`build_adapted()` 一条命令出完整镜像（含 DFU 后缀与 CRC 反码）。每条补丁只有三种结局：原位命中、按锚点搬移、拒绝。拒绝会说明是哪种：`unlocatable`（找不到）、`mismatch`（找到了但那儿不是这层要的字节）、`injection`（注入层且签名对不上）。**绝不硬改。**

## 实测

| 输入 | 套了几层 | 改动字节 | 产物 sha |
|---|---|---|---|
| 原版镜像（布局整体后移 0x400） | 3 层 | 2409 | `2245b2be12d8b15c` |
| clean 镜像（原位） | 只 widget | 2369 | `0becd247c8610d66` |
| 设备当前固件 `ov6p`（已注入、掩码全开） | 只换掩码 | 366 | `0becd247c8610d66` |

clean 原位那一行的产物 sha 与仓库里 `widgetlab/ov6q.bin` 的 `target_sha256` **完全一致** —— 说明适配器算出来的和手工构建出来的是一份东西。

另外做了一致性核对：直接调 `build_widget.patch()` 和走适配器的 `apply_entries()`，在三份迁移镜像 × 两种页掩码下产物**逐字节相同**。

回归：**121 项 Python + 8 组 node 全绿**，打包版 `--self-test` 11 项 PASS、`--gui-smoke` PASS。

## 和上一版的关系

v1.5.1 修的两件事（强制模式先试后写、文字组件默认关闭）在 1.6.0 里照旧。已经刷过 v1.5.1 的用户**不需要重刷**，这一版改的是「怎么算出该改哪儿」，不是「改什么」。

## 仍然没解决的

- **没有在真机上验证过自动适配的结果**。所有验证都是离线的：锚点唯一性、符号解析、产物哈希、两条路线逐字节相同。适配出来的镜像在别人机器上刷进去会不会正常启动，要等第一份真实反馈。这也是为什么 issue 流程只产出镜像、不替用户刷。
- 屏幕主控 `UB32F341S` 的 SWD/BOOT0 焊盘仍然没找到。屏幕代码区刷坏目前没有硬件恢复通道，只能靠那 180 秒的 bootloader 超时后自动回应用模式。
- 适配器只认 `491520` / `491536` 字节的键盘备份。屏幕固件、UI 资源包、接收器固件的长度都对不上，会直接被挡在门外。
- 注入层的空闲带如果被别的东西占了（固件比我们的大），这一层会跳过，前两层照打 —— 这种「三层只套两层」的情况在结论里会明写，但用户不一定看得懂。

风险清单（风险点 / 触发条件 / 后果 / 前兆 / 对策）共 10 条，见 [docs/adapt-any-firmware.md](adapt-any-firmware.md)。

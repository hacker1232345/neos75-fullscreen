# v1.9.0 — 两个旋钮，六个动作

发布日期：2026-11-05

## 这一版做了什么

键盘上方有两个旋钮：一个管音量，一个管屏幕翻页，两个还都能按下去。以前这六件事写死在固件里，
第三方工具改不了。这一版把六个动作位全部做成了可配置。

| 动作位 | 出厂 | 能改成 |
|---|---|---|
| 音量旋钮 · 顺时针 | 音量 + | 下一曲 / 上一曲 / 静音 / 播放暂停 / 亮度 / 计算器 / 邮件 / 主页 等 27 种 |
| 音量旋钮 · 逆时针 | 音量 − | 同上 |
| 音量旋钮 · 按下 | 静音 | 同上 |
| 屏幕旋钮 · 顺时针 | 下一屏 | 同上 + 翻页 |
| 屏幕旋钮 · 逆时针 | 上一屏 | 同上 + 翻页 |
| 屏幕旋钮 · 按下 | 计算器 | 同上 + 翻页 |

改完立刻生效。不装驱动，不依赖官方软件，也不用一直挂着进程。

## 怎么用

命令行：

```sh
python tools/knob_config.py --list
python tools/knob_config.py --fw keyboard.bin --out new.bin        --vol-cw next --vol-ccw prev --vol-press mute        --scr-cw page --scr-ccw page --scr-press calc
node   tools/knob_flash.js flash --target new.bin --yes
```

桌面程序：`两个旋钮，六个动作` 面板里有六个下拉框。`预览改动` 只在本机算，不碰键盘；
`写入键盘` 才会真的擦写，且先整片备份、写完逐字节回验、不一致就不固化。

## 为什么值得信任

**做出厂配置时，产物与官方固件逐字节相同**（md5 `24b5d4a6d1a53d6a7a93b20ccef9a416`）。
也就是说「恢复出厂」不是近似还原，而是真的回到官方那份固件。这一条有测试守着。

每次写入前都会先把整片固件读回并落盘到 `backups/`，写完再读回逐字节比对；只要有一个字节不对
就不发 manifest 固化，键盘会停在 DFU 而不是带着半截固件启动。

## 这一版踩平的四件事（写给以后要改固件的人）

1. **固件里有两份一模一样的「动作号 → HID 码」表**，真正被调用的只有前面那份。只改后面那份
   完全没反应——第一版实验就是这样白刷了一次机器。
2. **屏幕旋钮的左右旋转不发 HID 码**。它在固件内部直接给屏幕发 A5 帧翻页。要改它只能覆盖那两段
   代码，覆盖后必须跳回原函数出口 `0x080117BE`；中途自己 `pop {…,pc}` 会破坏栈，现象是
   「一拧旋钮键盘就重启」。
3. **`0x1a000` / `0x1b000` 两个扇区写不进去**：擦除和写入都报成功，读回还是旧值。所以不能新增
   代码块，所有改动必须原地做。
4. **「翻页」不是两个选项**。原厂那段代码自带方向判断，同一份字节放到顺时针位就是下一屏、
   放到逆时针位就是上一屏。拆成两个选项会出现「选了上一屏还往下一屏翻」。

## 顺带修好的两个 bug

- `knob_flash.js` 原来用 `dnload(空, wValue=2)` 发 manifest。`wValue=2` 被 DfuSe 当成「块号 2
  的空块写入」，设备只更新块指针、不固化重启，**写完键盘一直停在 DFU**。改成 `wValue=0` 后
  1.2 秒回到应用模式。
- 上面那条修好之前，`waitApp()` 是在 `close()` 之前调用的，等于握着旧句柄去等新设备重新枚举，
  永远等不到。现在先关句柄再等。

## 仍然没解决的

- 旋钮的**旋转**走的是固件内部路径，没有 HID 报告可抓（Windows 独占键盘集合，读不出来），
  所以「旋钮转了多少格」这类精细信息拿不到，只能按「一格一次动作」处理。
- 六个动作位之外，旋钮的长按 / 连按加速没有单独建位，跟原厂一致。
- 27 种动作里有几个是厂商私有 usage（`0x183`、`0x18a`、`0x192`、`0x194`、`0x221`…），
  在不同系统上是否能触发对应功能取决于系统有没有认这些 usage，这一版原样保留它们的编号。

## 装哪个

| 平台 | 文件 |
|---|---|
| Windows x64 | `Neos75-Windows-x64.exe` |
| macOS Apple Silicon | `Neos75-macOS-arm64.zip` |
| macOS Intel | `Neos75-macOS-x64.zip` |
| Linux x64 | `Neos75-Linux-x64.tar.gz` |

每个文件都带 `.sha256` 与 `.build.json`。macOS arm64 上没有 keystone 汇编器，
但屏幕旋钮那两段机器码已经预先算好存在 `tools/knob_code.json`，功能不受影响。

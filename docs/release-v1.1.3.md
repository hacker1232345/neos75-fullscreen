# Neos75 全屏工具 v1.1.3

读取或选择原始备份后，程序按代码区域哈希自动匹配固件配置。原验证构建和Issue #1构建使用同一个程序，生成、刷写及恢复均自动使用各自对应的补丁地址，**无需手动选择构建，也无需勾选“无验证”**。

| 构建 | 原版代码区域SHA256前缀 | 验证状态 |
| --- | --- | --- |
| 原验证构建 | `66679ff2…` | 原有图片/GIF实机验收通过 |
| Issue #1构建 | `74f2fa47…` | 新位置20条旧字节全部匹配，ARM仿真和刷写模型通过，实屏效果待验收 |

两种已补丁代码也会被识别为全屏版。生成结果、备份元数据和维护日志显示所选配置；界面明确标注实机验收与离线适配的区别。

继续严格核对原版哈希、全部补丁旧字节、输出代码哈希和目标重建一致性；每种构建只改27字节，保留本机其余内容及末尾4KB现场数据。完整备份及整片候选镜像不随项目发布。

“无验证，直接打补丁”仍默认关闭。未知构建默认拒绝；显式强制时使用原验证构建的固定地址，不代表能自动适配任意固件。Issue #1构建已重新定位，不要使用v1.1.2的旧地址强制模式。

Windows x64、Apple芯片Mac、Intel Mac均提供独立运行包。Mac支持macOS 15+，真实USB/DFU尚未在Mac验证。Windows无数字签名，Mac未Developer ID签名或Apple公证。

验证包括两份真实备份的Python/Node逐字节一致性、原/新目标哈希保持不变、全屏版识别、配置保留、代码改动拒绝及4KB/8KB擦除模型。公开测试使用合成数据，不包含设备转储。复盘与风险见 [自动适配复盘](auto-profiles-retrospective.md)。

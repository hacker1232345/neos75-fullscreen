# Neos75 v1.5.0：任意页覆盖组件（文字直写）

## 这一版做了什么

以前想在屏幕上显示电脑状态，只能把画面渲染成 JPEG 走官方的图片上传通道，再加刷新就变成了「反复擦写媒体区」。这一版加了一条完全不同的通道：**把四行文字直接写进键盘的内存**，不擦 Flash、不进 DFU、不占用 JPEG/GIF 上传队列。

配套的固件改动是**覆盖式**的：只改命令表 2 个字节，再往代码区的空闲带里放一小段自己的代码。**原厂 6 个页面的处理函数一个字节都没动**。

## 原厂页面全部保留

这一点和之前的实验分支不一样。分支的做法是把第 6 页的创建函数整段替换，第 6 页原本的内容就永久没了。现在改成「选中哪几页，就在那几页上叠一层」：

| 你选的页 | 行为 |
| --- | --- |
| 没选 | 完全原厂，图片、GIF、设置页一切照旧 |
| 选了 | 切到那页时叠加四行文字；图还在，文字压在上面 |

选页是运行时决定的，写在内存里，随时可改，不用重刷固件。

## 六个页面可以各自放不同的字

每个页面有自己独立的一份缓冲。翻到第 1 页看到的和翻到第 4 页看到的可以完全不同。

## 桌面程序

「小组件」页底部新增「直接写进键盘内存的四行文字」面板：

- 6 个「第 N 屏」按钮，点一下就在那屏开/关（未选白底，选中蓝底）
- 四行预览，实时显示当前会写上去什么
- 「检查设备」= 只读查当前页有没有装好组件，不写任何东西
- 「应用界面选择」= 把选好的页写进键盘内存
- 「发送一帧」/「连续发送」= 写一次 / 按间隔反复写

刷新间隔可选 2 / 3 / 5 / 10 秒。**实测 3 秒一帧稳定**，因为这条通道完全不碰 Flash。

## 固件侧的真实数字

| 项 | 值 |
| --- | --- |
| 改动字节 | 2369 B |
| 触及扇区 | 3 个 4KB 扇区（`0x35000`、`0x4a000`、`0x4b000`） |
| 页表 | 未改动（`page_table_untouched = true`） |
| 原厂页面处理函数 | 未改动（`vendor_enter_untouched = true`） |
| 目标代码 SHA256 | `dce6dce7…` |
| 真机状态 | 六个页面逐个推不同文字，全部 `acknowledged` |

写入方式沿用既有的最小写入：只擦写真正变化的扇区，其余字节不碰。刷前整片备份、逐扇区回验、`0x77000` 现场配置区硬保护，全部沿用。

## 协议

私有命令 `0x3D`，帧内 `A5 3D 00 LEN 00 4E 37 01 …`：

- `LEN=4` 只查能力
- `LEN=6+N` 写一行：第几个行号（0–3）、长度、ASCII 正文
- `LEN=6` 换页掩码：`0x7F`、长度 1、掩码位（bit0=第1页 … bit5=第6页）
- 应答两字节：`FE` 接受 / `FD` 该页尚未初始化 / `FC` 无效帧

`FD` 是正常的，不是错误：它的意思是「这条命令认了，但当前这页还没建组件对象」。翻到已选中的页面就好了。

## 只支持英文

固件的字模只验证了 ASCII `0x20`–`0x7e`。中文、emoji 会被替换成空格。四行、每行最多 47 字符，屏幕上是固定行高。

取不到的传感器显示 `n/a`（比如这台机器的温度就取不到），不编造数字。

## 兼容

补丁链仍然是纯哈希衔接：`原版 → 全屏 → 全屏+清爽 → 任意页覆盖组件`。已经在「全屏+清爽」的设备会被识别为可升级，只补最后一层。

## 仍然没解决的

- 屏幕主控（UB32F341S）的 SWD/BOOT0 焊盘一直没找到。如果屏板代码区刷坏，目前没有恢复通道。本版只改 3 个资源区扇区，不动引导和启动代码。
- 无线模式没验证过，只测了有线。
- 长跑只测了 40 轮 / 2 分钟级别，没做数小时监测。
- 屏幕不能主动退出 DFU，每次刷完靠约 180 秒超时或拔插回应用态。
- Mac / Linux 的 USB 侧仍未真机验证。

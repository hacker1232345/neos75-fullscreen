# Neos75 全屏工具 v1.7.0

这一版只修一件事：**陌生人刷「全屏补丁」不该再看到「设备固件不匹配」。**

v1.6.0 把「按偏移打补丁」换成了「按内容锚点定位」，但那套能力只做成了命令行工具，
桌面程序走的是另一条老路 —— 备份完一比对哈希，不认识就直接停下报错。于是普通人拿到的
结果是：**进度条还在**。很多人为了继续，只好去勾「无验证」，而那等于放弃所有校验、盲套固定地址。

## 现在会怎么走

备份完成后，如果哈希不在已知清单里，程序不再停下，而是：

1. 按内容锚点把每一层补丁要找的字节，在这份陌生固件里重新定位；
2. 逐层往前推进，一条对不上就停在这一层之前（不会出现「中间层没套上、后面那层却套了」的半套状态）；
3. 重新汇编注入层 —— 那 11 个厂商函数按 16 字节入口签名重新找出来，绝对地址全换成新的；
4. 核对尾部 4096 字节现场数据一个字都没动，再补上 DFU 后缀与 CRC。

界面文案从「固件不匹配」变成「已按锚点自动适配」。**但它不会空口承诺**：去进度条那一层在链中间，
程序会先看清那一层到底套上没有再说话 —— 套上了才说「进度条同样会被去掉」，漏了就说
「但还是没能套上去进度条那一层，浏览器上传时进度条会保留」，刷完的标题也跟着变成「补丁已完成（进度条仍在）」。

真的套不上时（比如对方把厂商函数改过了），程序停下来，但说的是一句人话：

| 情况 | 界面上的话 |
| --- | --- |
| 签名对不上 | 这份固件把小组件要用到的那几个厂商函数改过了（签名对不上），没法在不碰原厂逻辑的前提下把功能塞进去。补丁未做任何写入。 |
| 布局差得远 | 这份固件的代码布局和所有已知版本都差得比较远，连作为定位线索的字节都找不到。补丁未做任何写入。 |
| 旧字节位置被改 | 在旧字节该出现的位置找到了不一样的内容：这份固件可能已经打过补丁，或者被别的工具改过。请先把完整备份发上来。 |

再也不会把适配器算出来的原因用一句「操作已停止」盖掉。

## 刷写端也跟着改了

Node 那边的刷写器只会按固定偏移重算，算不出适配产物 —— 硬比必然失败。改成**核对产物本身**：

- 产物的 SHA256 必须等于生成端报上来的值（文件被换过就拒刷）；
- 尾部 4096 字节现场数据必须与现场一致；
- 前 256 字节向量表必须与现场一致；
- 有差异的扇区必须落在「已知补丁可能出现」的扇区白名单里，越界即拒。

这些检查从 `flash`/`restore` **上移到所有模式之前**，所以 `plan`（只读预检）同样受保护 ——
否则会出现「预检通过、真刷才发现文件被换掉」。

## 实测

| 输入 | 结果 |
| --- | --- |
| clean 镜像在 `0x9000` 插 0x400 字节、尾部挤出等量 | 自动适配成功，`changed=2369`，`adapted=true`，尾部现场数据未动 |
| 原版镜像改两处版本字节 | 三层全套上，`changed=2409`，产物代码前缀 `c435ad12fc29bff4` |
| 垃圾镜像（随机字节） | 抛出可读原因，不含堆栈 |
| 长度不对的备份 | 直接拒绝 |
| 适配产物被改尾部 / 改向量表 / 改到未预期扇区 | 三条独立拒绝，文案各自点名 |

离线：`python -m unittest discover -s tests` **127 项全绿**；`npm test` **8 组全绿**。

打包版（干净路径、不带仓库文件）实测：`--self-test` 11 项全 PASS；把一份**布局整体后移 0x400 字节**
的备份喂给它，`--build` 直接产出 `491536` 字节的完整镜像，`sha256=0efb304d…`、`adapted=true`、
`progressRemoved=true`。

> 这一版还有一处打包修复：`tools/build_widget.py` 是运行时加载的，里面用 keystone 重新汇编、
> 用 capstone 校验，PyInstaller 静态分析看不见，以前打包版一碰到陌生固件就报 `No module named 'keystone'`。
> 现在 `keystone.dll` 与 `capstone.dll` 一起带上了，体积 103.5 MB → 106.1 MB。

## 仍然没解决的

- **没有真机验证**：本机整轮设备不在线（HID 里只有摄像头、接收器、指纹模块），适配产物在真屏幕上能不能跑还没验过。刷写端那四条校验（SHA256/尾部/向量表/扇区白名单）只在本机用合成产物跑过，真机上线后会再验一次。
- 锚点依赖「这段字节在整片里唯一」，如果对方固件把同样的指令序列复制到多处，会主动拒绝而不是猜。
- 注入层依赖那 11 个厂商函数的入口签名。厂商大改编译参数（换优化级别、换 SDK）时签名会变，这一层就套不上 —— 前两层照打。
- 空闲带不够大时（`0x4aacc` 之后那段被别的工具用过），注入层无处落脚，同样只套前两层。
